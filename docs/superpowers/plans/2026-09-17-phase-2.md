# Phase 2A + 2B + 2C — Remote control, full workstation, browser automation

**Goal:** Phone → Internet → Cloud control plane → outbound agent → Windows
workstation, with capability-based filesystem roots, telemetry, uploads, and
Playwright browser automation. No rewrite of the Phase-1 trust core.

**Non-negotiables (all preserved):** pairing, device auth, granular
capabilities, risk classification, server+agent enforcement, single-use
approval binding, replay protection, STOP/cancel/pause, heartbeats,
revocation, append-only audit, redaction, before/after state, escape
protection. No autonomous decomposition, no financial auto-actions, no
external auto-comms, no creds to frontend, no inbound workstation ports.

## 2A — Remote connectivity (control plane)
- Job lifecycle: queued → authorized → dispatched → running → verifying →
  completed, plus failed/cancelled/denied/expired/stopped. `src/lib/control-plane.ts`
- Reconnect safety: stale running/dispatched jobs requeue to authorized
  (attempts capped at 3, then failed); revoked devices reclaim immediately;
  idempotent duplicate completion; idempotency keys on enqueue.
- Expiry: jobs + approvals TTL 24h, swept in reconcile().
- Rotation: POST /api/agent/rotate returns the new secret once; old dies
  immediately; agent CLI rotate.mjs; UI shows credentialRotatedAt.
- Rate limits: per-device agent polling, per-IP register/pair/mutations (429).
- Owner token: WAVES_OWNER_TOKEN gates /api/control/* (401 otherwise); UI
  sends it from localStorage; documented in docs/deploy-cloud.md.
- No-CORS + security headers in next.config.ts. Dockerfile + cloud guide.
- Stores stay file-backed but durable (atomic writes); Postgres path
  documented; no in-memory-only state.

## 2B — Full workstation (agent + policy)
- Protocol v2: 28 capabilities (fs.move/rename/execute, terminal.read/admin,
  applications.open/close/inspect/control, uploads.*, github.read/write),
  40 job kinds, policy {capabilities, roots, domains}, v1→v2 migration
  without weakening, admin command class, ADS refusal, multi-root
  resolution with pinning, domain allow/block with dot-boundary matching,
  secret-param scrubbing with binding hash.
- Roots: owner-managed via Settings; server + agent enforce lexical,
  realpath (symlink/junction), and ADS checks.
- Terminal: readonly→terminal.read; everything else gated; admin denied by
  default. stdout/stderr captured separately.
- Processes: allowlisted start, tracked-only stop, taskkill trees.
- Git: status/log/diff + approval-gated commit/push/pull/branch/checkout;
  github.issue/pr via detected gh CLI (honest refusal when missing).
- Uploads: approval-gated ≤15MB agent→cloud artifacts (screenshots,
  downloads, extracts, reports) with sha256; UI download.
- Telemetry on heartbeat: CPU (delta-sampled), memory, disk (statfs),
  process count, uptime, user, OS, detected tools, browser session.
- VS Code workflows ride proc.start (code) + terminal + git, all gated.

## 2C — Browser automation (agent/src/browser/)
- playwright-core + isolated Chromium profile (never the owner's browser:
  no owner cookies/passwords/tokens touch automation).
- 13 verbs: open/navigate/inspect/click/type/select/scroll/download/upload/
  screenshot/wait/extract/close. 30s timeouts, redacted logs (selectors and
  lengths only, never text/content).
- Domain policy enforced per navigation, both sides. data:/about:blank
  allowed (blank starts, offline tests); file:/chrome:/javascript: refused.
- Screenshots/downloads auto-upload as artifacts (upload failures never fail
  the local result). Typed secrets: TLS to the paired agent only, redacted
  in audit/UI, scrubbed from the store on completion (hash proof retained).
- No CAPTCHA defeat: stock headless Chromium, no solvers, no obfuscation.
- Honest unavailability: missing playwright/chromium → clear refusal.
