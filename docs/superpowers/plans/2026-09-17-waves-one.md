# WAVES ONE Interactive Prototype Implementation Plan

**Goal:** Deliver a mobile-first, interactive local CEO operating headquarters.
**Architecture:** Next.js App Router shell, typed pure domain transitions, browser-local persistence, reusable accessible dialogs. No external integrations, real AI, authentication enforcement, or machine access.
**Tech Stack:** Next.js 16, React 19, TypeScript, CSS tokens, Lucide, Vitest, Playwright.

## Approved design
Obsidian #090909, Carbon #111111, Graphite #181818, Steel #292929, Silver #A3A3A3, White #F5F5F5. Semantic colors communicate state only. Attention queue comes first. Desktop adds a sidebar and activity rail; mobile uses bottom navigation and review sheets. All demo actions are labeled simulated. Local changes persist. No credentials collected.

## Execution
- [ ] Domain: typed goals, tasks, approvals, incidents, workers, artifacts, connectors, audit events. Test duplicate decision prevention, rejected execution blocking, dependency gating, permissions, goal plan/delegation and persistence parsing before implementation.
- [ ] Shell: desktop sidebar, mobile bottom navigation with More menu, demo entry, command dialog, toast, persistence notices, accessible focus trapping and Escape handling.
- [ ] CEO loop: overview attention queue, approval evidence sheets with decisions, natural-language goal draft/review/delegate, linked work detail, simulated execution and verification.
- [ ] Supervision: people profiles and departments, files and provenance with local downloads, system and incident detail, activity filters, permission settings, computer-agent audit trail.
- [ ] Verification: unit tests; build and lint; mobile and desktop browser tests for decisions, new goals, task dependencies, command actions, persistence, reset, dialog keyboard handling, and overflow. Independent code/security review and fixes.

## File responsibilities
- src/lib/model.ts: shared types, initial realistic data, pure reducer, selectors, validation.
- src/lib/model.test.ts: state-machine regression tests.
- src/components/store.tsx: client persistence context.
- src/components/ui.tsx: icons, badges, dialogs, buttons, shared presentation.
- src/components/overview.tsx: attention-first home and daily brief.
- src/components/workspace.tsx: goal/work/people/files/system/activity/settings screens.
- src/components/flows.tsx: approval, goal, detail and command interactions.
- src/components/headquarters.tsx: shell, navigation, entry, global shortcuts.
- src/app/globals.css: OBSIDIAN responsive design system.
- tests/prototype.spec.ts: interactive desktop/mobile tests.

## Acceptance checks
Approve removes the pending item and writes an audit event but does not imply a real deployment. Reject never completes the job. New goal review creates dependent tasks before delegation. Task completion is blocked until dependencies complete. Agent pause and run generate visible events. High risk simulated action is held pending an explicit decision. Reload restores state; invalid storage safely falls back. The UI never claims real integrations or secure authentication. Mobile has no horizontal overflow and all primary actions remain reachable.
